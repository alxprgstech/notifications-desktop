# ALXPRGS Notify Desktop

Windows-приложение .NET 10 / WPF для подключения существующего чата Codex или DeepSeek Harness к разговорам Notify. Оно поддерживает одно выбранное подключение, работает в трее и восстанавливает исходящий WebSocket после сетевого сбоя. Речь распознаёт и синтезирует сервер Notify.

## Установка

1. Скачайте `ALXPRGS-Notify-Desktop-Setup-{version}-win-x64.exe` и соответствующий `.sha256` из [GitHub Releases](https://github.com/alxprgstech/notifications-desktop/releases). Сверьте SHA-256 командой `Get-FileHash -Algorithm SHA256 .\<имя-установщика>.exe`. Запустите установщик и откройте **ALXPRGS Notify Desktop** из меню «Пуск». Требуется Windows 11 x64. .NET Desktop Runtime входит в установщик, установка выполняется для текущего пользователя.
2. В кабинете Notify создайте источник с правом `agents:connect` и зарегистрируйте для него агента с возможностью живых звонков. Подтвердите операции в доверенном Android-приложении. Для инструментов MCP выдайте источнику только права на нужные операции.
3. В разделе **Подключения** введите HTTPS-адрес и токен источника. Agent ID и Source ID приложение получает через `GET /api/v1/agents/self`. Сервер Notify должен содержать этот маршрут и поддерживать разговоры с серверным распознаванием и синтезом.

### Обновление и удаление

Запустите новый установщик. Он завершает работающий процесс Notify Desktop, включая режим трея. Если открытый Codex держит файлы MCP, установщик Windows предложит закрыть использующие их процессы. Новый запуск восстанавливает сохранённое подключение. Настройки, чат и DPAPI-токен хранятся отдельно в профиле Windows. Удалите программу через **Параметры → Приложения → Установленные приложения**. Удаление сохраняет пользовательские данные и убирает запись автозапуска установленной копии.

Установщик и приложение пока выпускаются без Authenticode, поэтому Windows может показать предупреждение о неизвестном издателе. SSH-подпись Git подтверждает происхождение коммита. Файл SHA-256 позволяет проверить целостность скачанного установщика.

### Codex

Установите и авторизуйте Codex CLI. В Notify Desktop выберите **Codex**, откройте список через **Обновить список**, выберите существующий чат и нажмите **Подключить**. Если список ещё пуст, первое нажатие **Подключить** загружает его. Notify Desktop регистрирует `alxprgs-notify-desktop` через `codex mcp add`, проверяет `tools/list` и показывает статус WebSocket. В уже запущенном клиенте Codex для обнаружения новой регистрации может потребоваться перезапуск.

Кнопка **Найти доступный чат** проверяет сохранённые чаты из загруженного списка и выбирает первый, который Codex может открыть. Поиск не отправляет сообщений. Мост подключается к выбранному чату после нажатия **Подключить**.

Список сохранённых локальных чатов загружается через Codex App Server. При подключении приложение проверяет, может ли Codex возобновить выбранный чат. Если чат уже открыт в другом процессе Codex, освободите его или выберите другой. На реплику приложение вызывает `codex exec resume` для выбранного ID и читает итоговое сообщение из JSONL. Для этого запуска используется `read-only` и политика `never`. Сессии, доступные только в удалённой среде, могут отсутствовать в списке.

### DeepSeek Harness

Для первой установки плагина соберите соседний `harness-notify` командой `npm ci` и `npm run build`. В профиле Harness установите локальный bundle через **Settings → Plugins**. Если bundle уже установлен из того же каталога, достаточно пересобрать его и перезапустить Harness.

В Notify Desktop выберите **Harness** и нажмите **Подключить**. Откройте существующий чат в Harness и нажмите **Подключить этот чат** в панели Notify. Плагин передаёт реплики в этот чат через Session API и возвращает ответ через именованный канал Windows. Этот режим использует токен Windows-приложения для WebSocket. Встроенные инструменты Harness используют настройки и права своего плагина.

## Разговор и диагностика

- В Android откройте нужный источник и начните разговор с выбранной сессией агента. Статус **Агент на связи** в Notify Desktop появляется после серверного `hello_ack`.
- **Проверить соединение** читает регистрацию и статус через HTTPS. Повторная проверка во время разговора использует тот же HTTP-маршрут.
- Если статус сообщает о регистрации, откройте **Кабинет Notify** и проверьте источник и подтверждение Android. Если агент в сети, но Android не предлагает разговор, проверьте серверные STT и TTS и поддержку режима разговора.
- **Отключить** завершает текущее подключение. По умолчанию закрытие окна убирает его в трей. В **Настройках** можно отключить этот режим и выбрать светлую, тёмную или системную тему. **Выход** в меню трея закрывает приложение. Флажок автозапуска восстанавливает сохранённое подключение после входа в Windows. Плагин Harness восстанавливает привязку после перезапуска моста, пока чат открыт в том же сеансе Harness. После перезапуска Harness выберите чат заново.
- Настройки и зашифрованный DPAPI токен лежат в `%LOCALAPPDATA%\ALXPRGS\Notify Desktop`. Токен привязан к HTTPS-origin. В **Диагностике** можно скопировать Agent ID и Source ID. Журнал хранит последние пять статусов и не сохраняет реплики или токен на диск.

## Сборка и проверки

```powershell
./installer/Build-Installer.ps1 -Version 1.0.0 -Iscc "C:\path\to\ISCC.exe"
dotnet run --project tests/Notify.Desktop.Specs.csproj -c Release
dotnet run --project tests/Notify.Desktop.Specs.csproj -c Release -- --wss-soak
```

Тесты транспорта проверяют именованный канал, а также HTTPS-регистрацию, обрыв и восстановление WSS, heartbeat и возврат реплики на локальном TLS-стенде. Стенд использует временный сертификат и не меняет хранилище доверия Windows. Режим разговора поддерживает серверный STT/TTS. Голосовые файлы и отдельные фоновые задачи обслуживаются соответствующими агентами Notify.

Длительный тест принудительно обрывает WSS 40 раз. Он проверяет закрытие предыдущего сокета при каждом переподключении и выводит память и число дескрипторов общего процесса стенда и моста каждые десять соединений.

## Выпуск

1. Дождитесь успешного CI на коммите с проверенной SSH-подписью 1Password.
2. Для проверки без публикации запустите **Actions → Windows installer → Run workflow**. Скачайте установщик из артефакта `notify-installer`.
3. Опубликуйте GitHub Release для тега `vX.Y.Z`, указывающего на проверенный коммит. Workflow собирает установщик на Windows, проверяет чистую установку, обновление работающего приложения, сохранность DPAPI и удаление. После успешной проверки он добавляет к релизу EXE и файл SHA-256.

Smoke-тест создаёт синтетические данные в новом профиле Windows. Для локального запуска выделите чистый профиль, задайте `RUNNER_TEMP` и передайте `installer/Test-Installer.ps1` установщики baseline `0.0.0` и целевой версии.

Установленное приложение проверяет стабильные GitHub Releases при запуске и раз в шесть часов.
Установщик скачивается в профиль Windows и проверяется по SHA-256 из метаданных GitHub.
SHA-256 подтверждает целостность файла. Authenticode зависит от подписи самого установщика.
После нажатия «Установить» Notify ждёт завершения разговора, затем Inno Setup обновляет
приложение и запускает его в трее. Проверка и отмена доступны в **Настройки → Обновления**.
«Позже» скрывает предложение до перезапуска или ручной проверки.

Телефонный помощник использует отдельный источник Notify и существующий вход Codex CLI через ChatGPT.
После настройки серверного SIP-маршрута сохраните токен в **Настройки → Телефонный помощник**.
Там видны внутренний номер, доступность Codex и состояние разговора. ID сессии хранится в
`%LOCALAPPDATA%\ALXPRGS\Notify Desktop\phone-assistant\thread-id`.

## Фоновая работа

Окно и трей работают в одном WPF-процессе. Изменения состояния приходят от транспорта и системных событий. Сигналы показа окна и завершения ожидаются через Windows Events. Сетевой обмен в фоне поддерживает heartbeat протокола, а повтор подключения использует существующую задержку. Codex запускается для работы со списком чатов, проверки выбранной сессии и ответа на реплику. MCP запускается клиентом по stdio.

На Windows 11 (build 26100) в изолированной сборке с отключённым агентом после 5 секунд прогрева и 30 секунд в трее получено 0 мс дополнительного процессорного времени, 108,48 МиБ рабочего набора, 60,44 МиБ приватной памяти и 0 дочерних процессов. CPU измерялся разностью `Process.TotalProcessorTime`, память и число процессов снимались в конце интервала.

Локальный тест транспорта выдержал 40 принудительных переподключений WSS. На 10-м и 40-м соединениях общий процесс теста и моста занимал 27,17 и 22,04 МиБ приватной памяти, 654 и 653 дескриптора соответственно.
