# ALXPRGS Notify Desktop

Windows-приложение .NET 10 / WPF для подключения существующего чата Codex или DeepSeek Harness к разговорам Notify. Оно поддерживает одно выбранное подключение, работает в трее и восстанавливает исходящий WebSocket после сетевого сбоя. Речь распознаёт и синтезирует сервер Notify.

## Установка

1. Установите [.NET Desktop Runtime 10 для Windows x64](https://dotnet.microsoft.com/download/dotnet/10.0). Распакуйте сборку в постоянный каталог и запустите `ALXPRGS.Notify.Desktop.exe`. Для подключения Codex этот же файл запускается клиентом как MCP stdio.
2. В кабинете Notify создайте источник с правом `agents:connect` и зарегистрируйте для него агента с возможностью живых звонков. Подтвердите операции в доверенном Android-приложении. Для инструментов MCP выдайте источнику только права на нужные операции.
3. Введите в Windows-приложении HTTPS-адрес и токен источника. Agent ID и Source ID приложение получает через `GET /api/v1/agents/self`. Сервер Notify должен содержать этот маршрут и поддерживать разговоры с серверным распознаванием и синтезом.

### Codex

Установите и авторизуйте Codex CLI. В Notify Desktop выберите **Codex**, откройте список через **Обновить список**, выберите существующий чат и нажмите **Подключить**. Если список ещё пуст, первое нажатие **Подключить** загружает его. Notify Desktop регистрирует `alxprgs-notify-desktop` через `codex mcp add`, проверяет `tools/list` и показывает статус WebSocket. В уже запущенном клиенте Codex для обнаружения новой регистрации может потребоваться перезапуск.

Список сохранённых локальных чатов загружается через Codex App Server. На реплику приложение вызывает `codex exec resume` для выбранного ID и читает итоговое сообщение из JSONL. Для этого запуска используется `read-only` и политика `never`. Закройте или оставьте выбранный чат без активного хода в другом окне перед разговором. Обновление открытого окна Codex зависит от клиента. Сессии, доступные только в удалённой среде, могут отсутствовать в списке.

### DeepSeek Harness

Для первой установки плагина соберите соседний `harness-notify` командой `npm ci` и `npm run build`. В профиле Harness установите локальный bundle через **Settings → Plugins**. Если bundle уже установлен из того же каталога, достаточно пересобрать его и перезапустить Harness.

В Notify Desktop выберите **Harness** и нажмите **Подключить**. Откройте существующий чат в Harness и нажмите **Подключить этот чат** в панели Notify. Плагин передаёт реплики в этот чат через Session API и возвращает ответ через именованный канал Windows. Этот режим использует токен Windows-приложения для WebSocket. Встроенные инструменты Harness используют настройки и права своего плагина.

## Разговор и диагностика

- В Android откройте нужный источник и начните разговор с выбранной сессией агента. Статус **Агент на связи** в Notify Desktop появляется после серверного `hello_ack`.
- **Проверить соединение** читает регистрацию и статус через HTTPS. Повторная проверка во время разговора использует тот же HTTP-маршрут.
- Если статус сообщает о регистрации, откройте **Кабинет Notify** и проверьте источник и подтверждение Android. Если агент в сети, но Android не предлагает разговор, проверьте серверные STT и TTS и поддержку режима разговора.
- **Отключить** завершает текущее подключение. Закрытие окна убирает его в трей. **Выход** в меню трея закрывает приложение. Флажок автозапуска восстанавливает сохранённое подключение после входа в Windows. В Harness чат привязывается заново после перезапуска клиента или моста.
- Настройки и зашифрованный DPAPI токен лежат в `%LOCALAPPDATA%\ALXPRGS\Notify Desktop`. Токен привязан к HTTPS-origin. Журнал в окне хранит последние пять статусов и не сохраняет реплики или токен на диск.

## Сборка и проверки

```powershell
dotnet publish Notify.Desktop.csproj -c Release -r win-x64 --self-contained false -o artifacts/win-x64
dotnet run --project tests/Notify.Desktop.Specs.csproj -c Release
```

Тест транспорта проверяет реальный WebSocket поверх именованного канала с синтетическими репликами. Режим разговора поддерживает серверный STT/TTS. Голосовые файлы и отдельные фоновые задачи обслуживаются соответствующими агентами Notify.
